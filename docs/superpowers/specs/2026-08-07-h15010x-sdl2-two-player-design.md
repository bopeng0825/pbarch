# H15010x SDL2 双手柄双人设计

## 目标

为共用 H150101 SDL2 输入驱动的 H150101 和 H150102 平台增加两个玩家的独立手柄输入。SDL2 枚举到的 joystick index 0 控制 Libretro port 0（玩家 1），index 1 控制 port 1（玩家 2）。

## 范围

- H150101 与 H150102 同时启用双人支持。
- 只使用启动时 SDL2 枚举到的前两个 joystick。
- joystick index 0 映射到玩家 1，index 1 映射到玩家 2。
- 不假设玩家 1 必须是机身按键；H150102 可由两个 USB 手柄分别成为玩家 1 和玩家 2。
- 两个玩家采用相同的默认方向键和游戏按键映射。
- 两个手柄都能操作菜单。
- 其他平台的现有输入行为保持不变。

本次不实现运行时热插拔、玩家交换、菜单中的玩家分配、第三个及后续手柄、模拟摇杆 Libretro analog device 支持。

## 方案

在 `libpicofe/input.h` 的绑定类型中增加独立的 `IN_BINDTYPE_PLAYER2`。原有 `IN_BINDTYPE_PLAYER12` 继续作为玩家 1 的绑定类型，以避免改变其他平台和已有配置的含义。

H150101 SDL2 驱动只尝试注册 joystick index 0 和 index 1。每个驱动状态记录固定玩家：index 0 是玩家 1，index 1 是玩家 2。设备更新时，玩家 1 把默认游戏按键写入 `IN_BINDTYPE_PLAYER12`，玩家 2 把同一套游戏按键写入 `IN_BINDTYPE_PLAYER2`。模拟器动作仍写入 `IN_BINDTYPE_EMU`，因此两个手柄都可触发菜单。

玩家 1 保留原有注册名称 `h150101-sdl2:<name>`，避免已有单手柄按键配置失效；玩家 2 使用 `h150101-sdl2:p2:<name>`。这可以防止两个同型号 USB 手柄因名称相同而被通用输入注册层合并为一个设备。

`core.c` 将单个按键掩码改为两个元素：玩家 1 读取 `IN_BINDTYPE_PLAYER12`，玩家 2 读取 `IN_BINDTYPE_PLAYER2`。`pa_input_state()` 接受 joypad 的 port 0 和 port 1，并返回相应掩码；其他 port、device 和 index 仍返回 0。

## 数据流

1. 启动时 SDL2 按枚举顺序打开 joystick。
2. index 0 和 index 1 分别注册为 P1 和 P2；任一设备打开失败都不由更高 index 的设备补位。
3. 每帧 `in_update()` 调用两个设备的更新函数。
4. P1 和 P2 的游戏按键分别累计到两个绑定类型，模拟器动作共同累计到 EMU 类型。
5. 核心输入回调按照 Libretro port 返回相互隔离的玩家状态。
6. 驱动轮询某个设备时会暂存并重新入队属于另一设备的 SDL2 事件，确保游戏和菜单轮询都不会吞掉另一玩家的输入。

## 错误和边界处理

- SDL2 joystick index 0 或 index 1 打开失败时跳过该玩家；不会使用 index 2 或更高设备补位。
- 内存分配失败时关闭刚打开的 joystick，并停止继续注册，沿用当前驱动的失败行为。
- 第三个及后续成功可用的 joystick 不打开、不注册。
- 没有第二个手柄时，玩家 2 始终返回零输入。
- 两个手柄型号名称相同也必须注册为两个独立设备。

## 测试与验证

- 自动化测试先证明当前实现无法隔离 Libretro port 0 和 port 1，再验证两端口分别返回各自按键。
- 驱动测试验证前两个可用 joystick 的玩家编号、同名设备的唯一注册名称，以及第三个手柄被忽略。
- 回归验证单手柄仍控制玩家 1，菜单动作仍可用，非 joypad/非零 index/port 大于 1 返回 0。
- 运行仓库已有测试（若适用）、目标平台编译或至少相关源文件的交叉编译检查，并运行 `git diff --check`。
- 真机最终验收使用 H150101 或 H150102、两个手柄及支持双人的 Libretro 核心，确认两名玩家互不串键。

## 成功标准

H150101/H150102 启动时连接两个 SDL2 joystick 后，第一个只控制游戏玩家 1，第二个只控制游戏玩家 2；任一手柄均可进入菜单；单手柄和其他平台行为无回退。
